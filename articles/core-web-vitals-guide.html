Core Web Vitals Guide: Practical LCP, INP, and CLS Checklist

Treat Core Web Vitals as a release gate, not a buzzword. This is a checklist to run before shipping marketing pages and authenticated dashboards.

RM
By Ram
Published August 29, 2026 • Updated October 9, 2026 • 5 min read • ~1100 words

What you will learn

  • Trust field p75 from CrUX or RUM over a single Lighthouse run on desktop cable.
  • LCP usually needs a discoverable, prioritized, correctly sized hero image.
  • INP improves when you cut sync main-thread work after clicks and keypresses.
  • CLS is mostly reserved space: dimensions, banners, and font fallbacks.
  • TTFB and third-party tags often dominate real-user LCP more than micro-optimizations.
  • Ship RUM with attribution so you know which element and phase regressed.

The targets that matter

Google's “good” thresholds are LCP at or under 2.5s, INP at or under 200ms, and CLS at or under 0.1, at the 75th percentile of field data. Lab scores from Lighthouse on a fast connection can mislead. Prioritize CrUX and Search Console field data, then RUM from your own web-vitals beacons.

Lab and field numbers often disagree sharply. A storefront can score a green lab LCP while its field p75 is well over the threshold, because real users are on mid-range Android phones over mobile networks. When that happens, stop celebrating Lighthouse and work on the hero image and TTFB.

Split dashboards from marketing pages in reporting. Authenticated apps often look poor on LCP because the largest paint waits on an API. Mixing those cohorts can hide a homepage regression for weeks.

LCP: make the largest element arrive early

Find the LCP element in the Performance panel or the Web Vitals overlay. It is usually a hero img, an H1 block with a web font, or a product card image. Set explicit width and height or aspect-ratio, compress to AVIF or WebP, and add fetchpriority=high on the LCP image only — never on every image.

Preload that image in the head when it is not discoverable early. CSS background heroes are the worst offenders, because the browser cannot find them until the CSS has loaded; moving the hero into an img element is often one of the biggest single LCP wins.

The changes compound: cutting hero weight (a large JPEG to a much smaller AVIF), adding a preload, and removing lazy-loading from the LCP image together can move field p75 from failing to passing. loading=lazy on the hero image is one of the most common mistakes in PRs.

<!-- In <head> for known LCP image -->
<link rel="preload" as="image" href="/hero.avif" type="image/avif" fetchpriority="high" />

<img
  src="/hero.avif"
  width="1280"
  height="720"
  alt="Product dashboard"
  fetchpriority="high"
  decoding="async"
/>

INP: keep the main thread free after clicks

INP replaced FID. It observes every click, tap, and keypress during the visit, measures each from input until the next frame is painted, and reports roughly the worst one (ignoring rare outliers on pages with many interactions). A typical culprit is a filters panel that re-renders a table of thousands of rows synchronously on every checkbox toggle.

Fixes that move p75 INP: debounce expensive handlers (around 150ms), virtualize long lists, break up work with scheduler.postTask or requestIdleCallback for non-urgent updates, and avoid layout thrashing in event handlers. Profile with the Performance panel’s Interactions track instead of guessing.

Another common pattern: opening a modal that synchronously parses a large JSON blob and builds a chart. Moving parse and chart construction behind startTransition in React keeps the click responsive; the chart fills in a frame later. Users prefer a fast open over a frozen button.

// Bad: sync filter of huge list on every keystroke
input.addEventListener('input', (e) => {
  renderRows(filterAll(rows, e.target.value)); // freezes UI
});

// Better: debounce + yield
import { debounce } from './debounce';

const onFilter = debounce((value) => {
  const filtered = filterAll(rows, value);
  requestAnimationFrame(() => renderRows(filtered));
}, 150);

input.addEventListener('input', (e) => onFilter(e.target.value));

CLS: reserve space before paint

CLS spikes when ads, late fonts, or images without dimensions shove content around. Set image dimensions, use font-display: optional or swap with a close fallback metric, and reserve min-height for async embeds.

Cookie banners are a frequent CLS source: one injected above the fold without reserved space can push mobile CLS well past 0.1 on its own. Render a fixed-height placeholder for it in the initial HTML so nothing moves when it appears.

Web fonts are the other villain. A swap without matched metrics causes a visible jump of the H1. A fallback font with a similar x-height, tuned with size-adjust, makes the shift hard to notice.

  • Always set width/height or aspect-ratio on images and video
  • Avoid inserting DOM above existing content without a reserved slot
  • Prefer transform animations over top/left that trigger layout
  • Load webfonts with a fallback that has similar metrics
  • Test CLS with throttling and ad slots enabled — empty lab pages hide it

Wire RUM so arguments end

Ship the web-vitals library’s attribution build and POST LCP, INP, and CLS to your analytics endpoint with route name, connection type, and device class. Without attribution, “LCP is bad” is not actionable — you need the element and the phase, such as TTFB versus resource load versus render delay.

Sample at 100 percent on low-traffic marketing sites; on high-traffic apps, 5 to 10 percent still gives a stable p75 within a day. Alert when a route's p75 LCP rises sharply week-over-week after a deploy.

import { onLCP, onINP, onCLS } from 'web-vitals/attribution';

function send(metric) {
  const body = JSON.stringify({
    name: metric.name,
    value: metric.value,
    id: metric.id,
    route: location.pathname,
    navType: metric.navigationType,
  });
  navigator.sendBeacon('/rum', body);
}

onLCP(send);
onINP(send);
onCLS(send);

Images beyond the hero

Below the fold, use responsive srcset with 1x and 2x candidates and modern formats, and lazy-load everything that is not the LCP candidate. A product grid that eagerly loads a dozen large JPEGs competes with the hero for bandwidth and pushes LCP out.

Cap decoded size too. Serving a 4000px-wide asset into a 400px slot wastes memory and decode time on mobile; an image CDN can enforce max width by breakpoint. When a page insists on a video background, treat the poster frame as the LCP image and defer the video until after load or first interaction.

Server and cache levers that move field LCP

Many LCP regressions are really TTFB regressions. Edge-caching HTML for anonymous marketing pages with a 30–60s stale-while-revalidate, and keeping the API origin in the same region as users, often matters more than shaving 4KB of JS.

Audit third parties. A tag-manager container can add hundreds of milliseconds to mobile LCP. Defer non-essential tags until after requestIdleCallback or first interaction, and measure before and after with the same RUM dashboard — Lighthouse screenshots alone do not convince stakeholders.

A release checklist to paste into PRs

Before merge on customer-facing routes: identify LCP element; confirm preload and fetchpriority; no layout shift from fonts or banners; interaction handlers under about 50ms of sync work on mid-tier CPU; bundle diff does not add a new blocking script in head.

Fail the PR if lab LCP on a throttled mobile profile jumps by more than a set amount (say 300ms) without a documented reason. A rule like that catches accidental full-page client hydration of marketing content.

Keep a soft JavaScript budget for marketing routes (for example around 170KB gzipped). Crossing it requires a comment explaining the trade—enough social pressure to stop a charting library from sneaking onto the homepage. Paste lab LCP, INP, and CLS on a throttled mid-range phone profile next to the diff so reviewers stop arguing about vibes.
